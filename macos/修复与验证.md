# macOS 修订 3 — 输入修复与验证

构建号：2.4.10.3；验证日期：2026-10-18。
上游基线：afb06a7b18a040ab586f5ef247d13997bdb799b8。

## 本次发现的真实故障

- 旧进程 PID 49999 的 event tap 被系统保留为 mask=0x1000，仅 flagsChanged；keyDown/keyUp 被剔除。旧程序只检查 tapIsEnabled，因此误报连接成功，字母和井号都收不到。
- 授权后完整 mask=0x1c00 已恢复，字母进入监听，但井号仍然无效。真实系统路径复现为 asd#，不是 /p chat。
- 移除同步事件流中多余的前台 PID 校验，并让替换事件复制原事件路由后，同样输入得到 asd/p chat 。UI 自动化定向输入也揭示只读 session tap 覆盖不完整，因此两种模式统一到 annotated-session 层。

## 修复

1. 校验系统实际事件掩码；缺少 keyDown/keyUp 即视为未连接，不再将仅修饰键的 tap 报为成功。
2. 聊天过滤器创建失败时回退被动键盘监听；重试过滤器时保留已工作的监听，不中断字母动作。
3. “重新检测”确实重建 tap，授权变化触发重连；重启保留启动参数。
4. 前缀同步插入原事件流，并复制目标路由，避免依赖不同步的 NSWorkspace 前台 PID。
5. 两种监听模式覆盖相同事件阶段；忽略自身注入，避免额外敲击或递归替换。
6. 输入页显示按下/松开/替换计数、安全输入状态与连接错误。不保存输入字符或键码。
7. --input-diagnostics 是可选诊断开关，写入设置目录的 input-status.json，仅含计数、权限、版本和运行路径。

## 已执行验证

- Rust 42 项通过，含原版动画和桥接回归。render.rs 保持原样。
- Swift 91 条断言在 arm64 和 x86_64 Rosetta 分别通过，涵盖缺失事件掩码、原事件路由保留、按键收发、长按状态机和精确替换内容。
- 两种架构的 AppKit UI 回归通过：设置持久化、单次点击分发、固定权限入口、精确文本插入。
- 用户亲自授权后，用 UI 按键工具经过真实系统 event tap 测试：
  - 应用测试框输入 a/s/d/Shift+3，得到 asd/p chat 。
  - 文本编辑独立文档中连续两个 Shift+3，出现两个 /p chat 前缀，继续输入正常。
  - 最终构建关闭快速聊天后输入 a/s/d/Shift+3，得到 asd#，按下与松开计数各增加 4。
  - 重新开启后，在文本编辑中输入 Shift+3/q/w/e，得到 /p chat qwe。
  - 最终应用测试框输入单个 Shift+3，得到准确的 /p chat 加尾部空格，无回车。
- 最终运行状态：输入监控与辅助功能均获授权，事件掩码 0x1c00，主动过滤器正常，无超时。
- 正式 settings.json 与本次开始时逐字段比较无差异，皮肤和姿态保留。
- 通用二进制 arm64/x86_64，codesign --verify --deep --strict 通过。
