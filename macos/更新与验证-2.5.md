# macOS v2.5.0 — 控制台与音乐检测修订

验证日期：2026-10-29。macOS 2.5.0 已合入主线（Windows v2.5.2）且未覆盖 Windows 改动；macOS 功能仍停在 2.5.0，未跟进 Windows 2.5.1/2.5.2 新功能。应用版本及构建版本保持 2.5.0。

## 暂停后仍冒音符、署名（2026-10-29，仍为 v2.5.0）

- 原因：播放器暂停后可能不关闭输出流，继续送出静音，Core Audio 仍报告“正在输出”。
- Apple Music（com.apple.Music.playerInfo）与 Spotify（com.spotify.client.PlaybackStateChanged）会广播 Player State。现在监听这两条系统分布式通知，收到后以广播为准，暂停即停；播放器退出时清除其状态。新旧系统路径都适用。
- 网易云音乐与 QQ 音乐没有公开的播放状态广播，仍以输出流判断。--probe-audio --watch 每秒列出每个播放器进程的输出状态，共 30 秒，用于确认暂停后哪个进程仍保持输出。
- 删除控制台右下角的制作署名（仅 macOS），回归测试检查控制台不再出现署名。
- 验证：两架构 191 项断言（91 + 100）及 AppKit、冒烟、重启、登录启动回归通过。暂停行为待人工实测。

## 权限颜色与音乐播放器限定（2026-10-29，仍为 v2.5.0）

- 输入权限窗口改为三色：输入监控（键盘实际连接）与辅助功能都生效为绿色，只有一项为黄色，都没有为红色。首行列出所有缺少的项；控制台开关名称未改。
- “清除旧记录”的 tccutil 参数改由一个函数生成，只接受本应用的标识 com.dlmember.minecraft-desktop-pet.macos；拿不到标识或标识不同时不执行，避免误清其他应用的授权。新增自检覆盖。
- 音乐音符只跟随网易云音乐（com.netease.163music）、QQ 音乐（com.tencent.QQMusicMac）、Apple Music（com.apple.Music）、Spotify（com.spotify.client）及其辅助进程（标识加后缀，如 com.netease.163music.helper）。浏览器、游戏、afplay 等不再触发。macOS 12.0–14.1 回退为“播放器已打开且输出设备在运行”。
- --probe-audio 诊断输出改为显示正在播放的播放器标识。

### 本轮验证

- Swift 输入与平台：arm64、x86_64 各 179 项断言通过（91 + 88），新增三色规则、tccutil 参数限定本应用、播放器标识匹配与过滤断言。
- 两架构 AppKit 回归（权限窗口颜色与三色规则一致）、冒烟、重启、登录启动（--autostart）回归均通过；ad-hoc 签名严格验证通过。

## 合入主线后的修复（2026-10-29，仍为 v2.5.0）

- 共用的 native/Cargo.toml 保持 Windows 的 2.5.2；macOS 构建脚本临时改为从 macos/Info.plist 读取版本，产物名为 2.5.0。追上 Windows 版本后改回读取 Cargo.toml。
- 交替打字模式：原先没有键位的那只手只下沉约 6°，看起来像没在敲。macOS 下改为落到这只手所在半边的主键行，幅度约 17°（Q 版约 21°），与精确模式（约 18°）相当；另一只手不动。Windows 行为不变（cfg 限定 macOS）。删除临时探测测试，换成 macOS 专属的幅度断言。
- 开机时打开控制台：同时存在本应用的 LaunchAgent 和系统设置里的登录项时，第二次启动会以“重新打开”事件到达，从而打开控制台。现识别 open-application 事件里的 keyAELaunchedAsLogInItem，按登录启动处理；登录启动后的重新打开事件不再打开控制台。
- 菜单栏切换“点击穿透”“置顶”“快速聊天”只修改设置，不再打开控制台；控制台已打开时只同步其中的开关。
- 输入权限窗口：所需权限未生效时整窗红色，全部生效后绿色，首行写明问题（已由上节三色规则替代）。
- 拖动授权：点击申请按钮后打开系统设置对应列表，等待窗口位置稳定后在旁边显示可拖动的应用卡片，拖入列表即可添加。做法参照常见的 macOS 授权引导（如 MIT 许可的 AskForPermission），代码为本仓库自写。
- 关于“只能在本应用窗口内敲字”：临时签名（ad-hoc）每次构建 CDHash 都会变，系统按旧 CDHash 保存的授权会显示为已授权，但事件监听拿不到普通按键。窗口会把这种情况标红并提示删除旧条目后重新拖入。已安装的旧构建（10-25）实测正常：event tap 连接，其他应用中的按键被计数。

## 此前修改

- 控制台参照 Windows 版：三页横向按钮、分行标签、原生单选按钮、整行滑杆、右下角 GitHub 图标，以及“由 GPT 6 Astra 制作”署名；深浅外观沿用 macOS。
- “恢复内置”仅恢复内置皮肤，保留姿态、披风、自启与其他偏好；“恢复默认”仍为单独的完整重置操作。
- 音乐检测改用公开的 Core Audio 输出活动属性（播放器限定见最上节），无录音、音频采样、播放器自动化请求或私有接口。删除界面中原来的两款播放器限制说明。
- macOS 14.2+ 查询活动输出流；旧系统使用输出设备运行状态。该功能不是音乐内容或音量识别：网页、游戏和维持输出流的静音程序也可能触发；旧系统双向音频设备可能因输入活动而运行。
- 登录自启不再因键盘权限未就绪而打开控制台；禁用控制台窗口状态恢复。仍可手动从菜单栏或双击桌宠打开设置。
- 关闭控制台时释放页面控件；音乐状态未变化时不反复唤醒渲染。
- GitHub 图标直接复用仓库的 assets/github.svg，保留随包分发的 Octicons 许可。

## 内存实测与限制

本机 arm64，macOS 27.0；单进程 phys_footprint，十进制 MB，约 73 秒隔离压力测试，输入 event tap 在压力测试中关闭。测试包括持续动画、十二次控制台开关、导入 1024×1024 皮肤、隐藏及恢复。

- 静置最低约 26.0 MB，静置阶段短时最高约 40.0 MB。
- 持续动画约 40.2–40.7 MB。
- 控制台反复切换/开关峰值约 91.9 MB；关闭后约 81.0 MB。
- 高清皮肤阶段约 85.2 MB；隐藏后约 75.2 MB。

**尚未满足 30 MB 的全场景/峰值目标。** CONTRIBUTING.md 原文将 30 MB 限定为 Windows；本记录保留 macOS 的实际结果，不能把短时静置数字当作峰值或所有使用场景的保证。此次扩大控制台布局后的结果也不能沿用上一候选版约 86 MB 的峰值数字。
