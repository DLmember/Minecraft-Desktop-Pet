# macOS CPU 优化验证（本地候选版）

## 范围与原因

对应 [macOS CPU 占用反馈](https://github.com/DLmember/Minecraft-Desktop-Pet/issues/11)。Issue 只有占用截图，没有机型、皮肤或开关配置，不能据此认定反馈用户的唯一根因。

本机采样发现 CPU 光栅化 `Frame::triangle` 是主要热点。macOS 仅开启 DA 眨眼时，原来的 FFI 不检查当前眨眼相位，整个间隔也持续重绘；持续呼吸则跟着用户设置以最高 120/240 FPS 绘制。画布原先固定 450×525，缩小窗口不减少像素工作。

## 本地改动

- 眨眼只在闭合/恢复期间要求绘制，间隔休眠；保留最后睁眼帧。
- 区分静止、仅呼吸、动态动作。仅呼吸绘制约 15 FPS；鼠标跟随、打字、挥手、PAT 等恢复用户设置的交互帧率上限，保存的 FPS 不变。呼吸周期仍用真实时间计算。交互后的 0.85 秒恢复窗口不变。
- 小窗口使用更小画布；65% 为 293×341，100% 及以上保留原来的 450×525 上限，不因放大而增加超过原版的像素预算。CGImage、双缓冲长度和命中检测使用实际画布尺寸，旧图像保留自己的内存直到合成器释放。
- 小于等于 128 像素宽的皮肤预计算颜色（最大约 288 KiB）；高清皮肤仍使用省内存查色表。缓存键盘面光照，避免每个三角形重复计算幂函数。
- macOS 光栅化先求出扫描线被三角形覆盖的整数区间，不再遍历矩形范围内所有外部像素。保留相同半开边规则，并对照原算法验证像素、深度和包围盒一致（含旋转、半透明皮肤、简洁/细节键盘、普通/Q 版及不同姿态）；另检查 5,000 组随机半平面区间。
- 不使用多帧呼吸缓存、不增加 GPU 框架、不修改 Windows 可执行程序入口或 Windows 的刷新策略。

## 测量方法

`--cpu-test --data-dir <独立目录>` 禁止真实鼠标点击、键盘输入、音频播放和正式登录项变更；`gaze` 场景用模拟坐标，不移动真实鼠标。测试预热 3 秒，再以进程 user+system CPU 时间除以实际墙钟时间测量 8 秒，同时记录帧数和 phys_footprint。

使用 `scripts/benchmark-macos.py`，每场景重复三次，旧版/新版交替执行并每轮反转顺序。测量过程中不同时编译或运行其他桌宠测试。报告中位数，CPU 的 100% 约等于一个逻辑核。测试机为 Apple M1；Intel 只经 Rosetta 验证功能，不能代表实体 Intel 性能。

旧版来自本轮开始前提交，仅加入相同测试入口与输入隔离；不是拿不含测试模式的正式应用直接运行测试参数。两版使用同一个合成眨眼皮肤，关闭音乐、全局键盘和实际鼠标跟随；交互测试和 gaze 场景除外。基准不是所有皮肤、高清纹理或所有用户环境的性能保证。

仅呼吸的节省包含降低绘制频率的收益，不能声称是“保持 120 FPS 的同等画面性能”。平滑程度和真实使用下的表现仍需人工试用。

## 运行方式

先用 `scripts/build-macos.sh` 构建候选包，再运行（输出目录必须不存在）：

```bash
python3 scripts/benchmark-macos.py '/path/Minecraft桌宠.app' /path/new-results --trials 3
```

对比有相同测试入口的旧版：

```bash
python3 scripts/benchmark-macos.py '/path/new/Minecraft桌宠.app' /path/comparison --baseline '/path/old/Minecraft桌宠.app' --trials 3
```

结果保存在 `results.json`。不修改 README、版本号或已安装应用，不自动提交和发布。

## 实测结果（2026-11-09，Apple M1 / macOS 27.0）

以下为交替运行三次的中位数；旧版为 `4f5450d` 加相同测试入口，新版为本地候选。CPU 百分比基于进程累计时间，不包含其他进程的 WindowServer 开销。

| 场景 | 旧版 CPU | 新版 CPU | 旧版实际 FPS | 新版实际 FPS |
|---|---:|---:|---:|---:|
| 仅呼吸，65%，设置 30 FPS | 9.29% | 4.28% | 30.0 | 15.1 |
| 仅呼吸，65%，设置 60 FPS | 18.59% | 4.66% | 60.0 | 15.0 |
| 仅呼吸，65%，设置 120 FPS | 22.89% | 4.63% | 119.9 | 15.0 |
| 仅呼吸，100%，设置 30 FPS | 10.22% | 6.65% | 29.9 | 15.0 |
| 仅呼吸，100%，设置 60 FPS | 20.31% | 5.76% | 59.9 | 15.0 |
| 仅呼吸，100%，设置 120 FPS | 26.76% | 5.93% | 120.0 | 15.0 |
| 静止，65% | 0.70% | 0.64% | 0.0 | 0.0 |
| 仅眨眼，65% | 25.73% | 1.64% | 119.9 | 3.5 |
| 挥手/PAT 循环（本轮未启用键盘） | 30.06% | 17.07% | 120.0 | 110.6 |
| 持续模拟视线跟随，65% | 28.80% | 17.07% | 119.9 | 120.0 |
| 隐藏 | 0.07% | 0.06% | 0.0 | 0.0 |
| 控制台打开，模型静止 | 1.78% | 0.90% | 0.0 | 0.0 |

眨眼的平均绘制 FPS 很低，是因为两次眨眼之间不绘制；眨眼进行时仍使用交互帧率上限。仅呼吸的周期不变，但绘制为 15 FPS，视觉平滑程度请实际试用。

本轮 65% 呼吸场景 phys_footprint 中位数约 30.8 → 26.1 MB；100% 呼吸约 39.5 → 34.5 MB；控制台打开约 49.8 → 47.2 MB。此任务没有实现全场景低于 30 MB 的承诺，也不能把低负载瞬间内存当成峰值。

## 最终回归

- arm64 / x86_64：Rust 各 101 项通过、4 项忽略；Swift 输入与平台各 207 项通过。
- 两架构 UI、冒烟、启动和重启测试通过；单芯片 ZIP 解压后的签名和输入自检通过。
- 新增：眨眼间隔/最后恢复帧、呼吸淡出、交互优先级、画布尺寸/非有限坐标边界、双缓冲旧图像所有权、隐藏/恢复、扫描线覆盖与像素一致性测试。
- 输出在 `release/cpu-optimized/`，与正式 `release/macos/` 分开；版本保持 2.5.3，未安装、提交、推送或上传 release。
- CPU 数据是短时隔离测试；仍需用户确认真实键盘输入、呼吸观感、长时间工作和不同皮肤表现。帧率越高的主动互动仍可能占用十几个百分点，本轮没有把所有场景都降到低个位数。
